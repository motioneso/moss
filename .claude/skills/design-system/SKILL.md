# The authored design system

The design system is **authored, not generated**. The reference is `docs/design-system.md`. Read
it before UI work. The shipped CSS wins over any doc: `apps/web/src/styles/tokens.css` for tokens,
`packages/ui/src/styles/` for shared primitives. Today is the reference page.

## Rules that get broken most

- Headings `--font-display` (Archivo), everything else `--font-sans`. No serif anywhere. Monospace
  only for real code (chat code blocks, snippets).
- Raw colours live in `tokens.css` alone. Use semantic tokens so every theme works.
- First-party modules (everything in this repo) use `@moss/ui` components and tokens fully; their
  own CSS is layout only. Third-party modules may style freely. News and Sports module styling is
  known debt, not precedent.
- Use a `@moss/ui` component before a raw `jds-*` class, and a listed option before a new one.
  Check `packages/ui/OPTIONS.md` (generated by `pnpm build:ui-catalogue`).
- Missing a primitive? Add it to `packages/ui/src/` and `packages/ui/src/styles/`, never work
  around it in the calling surface.
- Sections are hairline-ruled, not boxed in cards. No curved accent left border.
- Empty and loading states follow the patterns in `docs/design-system.md`. Don't render a section
  with nothing useful to say.

## The invented-class audit

A `jds-*` class the design system never defined still renders — as nothing, silently. Run this
before any UI design pass (adjust the first path to the surface you're auditing):

```bash
grep -rhoE "jds-[a-zA-Z0-9_-]+" <surface-src-dir> | sort -u > /tmp/used.txt
grep -rhoE "\.jds-[a-zA-Z0-9_-]+" apps/web/src/styles/ packages/ui/src/styles/ | sed 's/^\.//' | sort -u > /tmp/defined.txt
comm -23 /tmp/used.txt /tmp/defined.txt
```

Names ending in `--` or `-` (`jds-btn--`, `jds-badge--`, `jds-card--pad-`) are prefixes of
classes built at runtime; the full names are defined. Auditing `packages/ui/src` itself also
prints three bare hooks with no styles of their own (`jds-masthead`, `jds-masthead__clock-time`,
`jds-combobox__search`) and two animation names (`jds-menu-in`, `jds-pulse`). Anything else it prints is a defect, not a style opinion. Module-local
class hooks fail the same way — audit them against their own stylesheet too.

`pnpm check:ui-classes` runs the same check across the repo and tracks the runtime-built names.
