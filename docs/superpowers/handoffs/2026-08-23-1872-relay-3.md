## What's actually stuck: `pnpm db:migrate` against the gate database

This is the last untested step before `pnpm test:uat-seed` and `pnpm test:integration` can run.
Twice in a row it failed with **"schema app does not exist"** even though I confirmed by hand
(direct `psql` as the migration role) that the schema and even the migration-tracking table
already existed in that database. Then, running it a third time by hand in the foreground, it
failed differently: **"tuple concurrently updated"** while applying the grants files — a real
Postgres error that only happens when two sessions write the same row at the same time.

**My read:** I likely had two copies of the migration step running against the same gate database
at once — once via a background script I'd started, and once when I ran the command again by hand
without confirming the background one had actually finished first. That would explain both
symptoms: the "schema does not exist" error from one session reading a half-committed change made
by the other, and the later literal concurrency error. I did not get to prove this before running
out of room to keep investigating — **that is exactly what you should check first.**
