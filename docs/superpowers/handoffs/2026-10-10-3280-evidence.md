## Live proof

Installed copy of this branch, run on its own throwaway database. Nothing pointed at the shared dev
database.

| Setting | Value |
|---|---|
| Chat model | Claude CLI sign-in, `claude-haiku-4-5-20251001` (economy tier); no API keys |
| Embeddings | local `nomic-ai/nomic-embed-text-v1.5`, real query embeddings on every recall |
| Email | GreenMail container as a disclosed stand-in mail server, 6 ordinary seeded messages, read through Moss's real IMAP connector |
| Spec | `tests/live/pool-hang-3027-uat.spec.ts`, Playwright live config, trace off |

Each run opens Conversations, clicks New side chat, waits for the drawer clear (asserted 204) and
an empty transcript, then sends a message that needs the email tool. Recall calls and health
probes run from before the side chat starts until after the turn returns.

| Measure | Run 1 | Run 2 | Limit |
|---|---|---|---|
| Turn status | 200 | 200 | 200 |
| Turn time | 11,433 ms | 9,767 ms | under 120,000 ms |
| Reply length | 691 chars | 503 chars | non-empty |
| Recall calls | 7, all 200 | 8, all 200 | all 200 |
| Health probes | 240, all 200 | 209, all 200 | all 200 |
| Health p50 / max | 1 ms / 73 ms | 1 ms / 17 ms | max under 500 ms |
| Spec result | 1 passed (16.7 s) | 1 passed (13.3 s) | |

The matching email step in both runs is the line `Tool` + `mcp__moss__email_listVisibleMessages`.

Chat threads in the copy's database went from 2 before run 2 to 3 after it, so each run starts its
own conversation. When the drawer was opened between runs, it showed the empty start screen, so
there was no earlier reply on screen for the clear to remove.
