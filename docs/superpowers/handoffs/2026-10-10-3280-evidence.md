## Live proof

Installed copy of this branch, run on its own throwaway database. Nothing pointed at the shared dev
database.

| Setting | Value |
|---|---|
| Chat model | Claude CLI sign-in, `claude-haiku-4-5-20251001` (economy tier); no API keys |
| Embeddings | local `nomic-ai/nomic-embed-text-v1.5`, real query embeddings on every recall |
| Email | GreenMail container as a disclosed stand-in mail server, 6 ordinary seeded messages, read through Moss's real IMAP connector |
| Spec | `tests/live/pool-hang-3027-uat.spec.ts`, Playwright live config, trace off |

Each run opens Conversations, clicks New side chat, waits for the drawer clear (asserted 204) and
an empty transcript, then sends a message that needs the email tool. Recall calls and health
probes run from before the side chat starts until after the turn returns.

| Measure | Run 1 | Run 2 | Limit |
|---|---|---|---|
| Turn status | 200 | 200 | 200 |
| Turn time | 11,433 ms | 9,767 ms | under 120,000 ms |
| Reply length | 691 chars | 503 chars | non-empty |
| Recall calls | 7, all 200 | 8, all 200 | all 200 |
| Health probes | 240, all 200 | 209, all 200 | all 200 |
| Health p50 / max | 1 ms / 73 ms | 1 ms / 17 ms | max under 500 ms |
| Spec result | 1 passed (16.7 s) | 1 passed (13.3 s) | |

Runs 1 and 2 used the branch before it merged the integration branch (41 commits). After the merge
the copy was migrated and its API, worker and web were restarted, then the spec ran again.

| Measure | Run 3 (merged) | Run 4 (merged, runner restarted) |
|---|---|---|
| Turn | 200 in 1,781 ms, empty reply, no steps | 200 in 10,761 ms, reply 388 chars |
| Recall calls | 2, all 200 | 8, all 200 |
| Health probes | 77, all 200, max 108 ms | 223, all 200, max 23 ms |
| Spec result | 1 failed | 1 passed (15.6 s) |

Run 3 failed because the turn came back empty. The private chat runner was still the one started
before the merge. It opened the chat session and listed the tools, then returned no reply and logged
no error. Restarting only that runner fixed it, and run 4 passed. The cause was not pinned down
further. The test code did not change between runs 3 and 4.

The matching email step in runs 1, 2 and 4 is the line `Tool` + `mcp__moss__email_listVisibleMessages`.

Chat threads in the copy's database went from 2 before run 2 to 3 after it, and to 5 after run 4,
so each run starts its own conversation. When the drawer was opened between runs 1 and 2, it showed
the empty start screen, so there was no earlier reply on screen for the clear to remove.
