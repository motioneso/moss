# 3365 live proof: the chat gate now waits long enough for a slow routing model

Run on 2026-10-10, on an isolated copy of Moss on this box (its own database, its own private
command-line runner signed in with the project's encrypted test token, its own API, worker and web).
The shared dev database, the shared runner and prod were not touched.

## What ran

- Code under test: commit ea690b6c0 (time recorded per question, limit sized for a full
  four-question attempt). The later commit ae7658aae changes only app-map wording, one test and one
  code comment, so the gate behaves the same as on ae7658aae.
- Baseline: commit c24c51779 (before 3365, fixed 3 second limit), same database and settings.
- Routing model: claude-haiku-5-5 through the Claude command-line sign-in (cheapest Claude model).
- Settings were made through the real Settings screen as the instance admin: AI providers, Refresh
  models, Classifier model set to claude-haiku-5-5, Chat gate set to Shadow.
- Messages were typed into the chat drawer. Only the decision, reason, latency, module and tool
  columns of the shadow records were read, plus the model call timings from the activity log.

The API was restarted on ea690b6c0 at 13:50, so the first message had no speed record yet.

## What it shows

- With the fixed 3 second limit, every attempt from this model timed out, so the gate could never
  help.
- With the measured limit, the first attempt after a restart got the 30 second starting wait and
  finished with a real decision in 17.4 s. Every later attempt also finished with a real decision,
  in 13 to 16 s.
- By the new rule, this model's measured time per question (about 5.8 s at worst) times four
  questions, doubled, is well over 30 s, so its limit stays at the 30 second ceiling. Every attempt
  here finished well inside it.

## Notes

- For this model the measured limit always lands on the ceiling. The measurement only lowers the
  wait for a model that answers a question in under about 3.7 seconds.
- In these runs the main model's own answer took about 5 to 7 seconds, while the gate took 13 to 17
  seconds. In Shadow this costs nothing. If the gate is ever turned On with this model, a quick
  action would likely reach the user later than the main model's reply would.
