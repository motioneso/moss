# Issue 3128 evidence: returning safely to an interrupted conversation

Live proof for PR 3370 on branch `scheduled/3128-interrupted-return`, run on 2026-10-10.
Times are UTC from the server log. Ids are shortened to their first 8 characters.

## Setup

| Item | Value |
|---|---|
| Commit | `3af9d56d8`, built into a local image from a clean export of that commit |
| Model | `claude-haiku-5-5` through the Claude command-line sign-in |
| Sign-in | the project's encrypted test sign-in, written into the install's own sign-in volume |
| Install | production-style install (the prod compose file), its own project name, one database container and one app container |
| Isolation | own containers, volumes, network and image tag; nothing shared with prod or the shared dev database |
| Account | a fresh owner account created through the sign-up screen; setup wizard completed in the UI |
| Embeddings | test embeddings, to keep memory use low; chat does not depend on them |
| Browser | headless Chromium driven by Playwright through the real UI; network never intercepted |

The demo used the production-style install on port 5199, not port 5186, because 5186 was busy
with another session's server.

The kill was a hard kill of the API process inside the app container. The container's supervisor
then stopped the other processes and the container restarted, so every restart is a new server
process with a new boot id.

### 3. Exchange A

- Question: "What is the capital of France? Answer in one short sentence."
- Answer: "Paris is the capital of France.", shown with the model name `claude-haiku-5-5`.
- The chat is the saved main chat (not private), thread `aed6bb42`.

### 4. Question B and the hard kill

Two earlier attempts at B (Roman aqueducts, Great Wall of China) finished before the kill landed.
Haiku wrote each 800-word answer in under 30 seconds, and the chat shows a reply only once it is
complete. Both are stored as normal finished exchanges, once each. The kill was then timed from the
in-flight row instead of from visible text.

- B: "Write a detailed, multi-paragraph history of the printing press ..." sent at 22:49:26.
- The in-flight row for turn `c1525d23` appeared at once. Eight seconds later the Stop button was
  still showing, so the reply was still running. The API was killed at 22:49:34.
- Database straight after the kill: one in-flight row, turn `c1525d23`, thread `aed6bb42`,
  boot `4093f6aa`, holding the question. Nothing for B in the saved messages.
- After the restart the row was still there, unchanged.

### 5. Reopen after the restart

The second reopen, the final screen, and a repeat run all showed the expected text. The screen
reads, in order:

```
What is the capital of France? Answer in one short sentence.
Paris is the capital of France.
(Roman aqueducts question and its full answer)
(Great Wall question and its full answer)
Write a detailed, multi-paragraph history of the printing press, covering Gutenberg's workshop, ...
Moss was interrupted before finishing this reply. Anything it started may not have completed, so check before asking again.
What is 12 times 12? Answer with just the number and nothing else.
144
Write a detailed, multi-paragraph history of the London Underground, covering the first steam line, ...
Moss was interrupted before finishing this reply. Anything it started may not have completed, so check before asking again.
```

Both notes are drawn with the chat's normal error style (`form-error`). A appears once.

On the very first reopen after the first restart, the screen showed A and the two finished
exchanges but not B or its note, although the database had already converted B. The next reopen
showed both. A repeat with question B2 (London Underground: killed 8 seconds in, Stop showing)
was watched more closely. The history request on the first reopen returned 12 messages with 2
error notes, and the screen showed both notes. So the miss happened once and did not happen again.
Its cause was not found. During that first reopen the server had only just restarted, and one
startup request took about 6 seconds.

### 6. Question C

"What is 12 times 12? Answer with just the number and nothing else." The answer "144" came back
from the model in about 5 seconds, after B's note, and was stored normally.

## No resend after the restart

The server log records every question sent to the model as one `POST /api/chat/turn` request:

```
22:43:10 POST /api/chat/turn    A
22:44:00 POST /api/chat/turn    Roman aqueducts
22:47:33 POST /api/chat/turn    Great Wall
22:48:01 api exited SIGKILL     (landed just after the Great Wall reply was saved)
22:48:20 API started
22:49:26 POST /api/chat/turn    B
22:49:34 api exited SIGKILL
22:49:53 API started
22:53:51 POST /api/chat/turn    C, typed by the browser
22:54:39 POST /api/chat/turn    B2
22:54:47 api exited SIGKILL
22:55:09 API started
```

No question went to the model between the restart at 22:49:53 and C at 22:53:51, though the chat
was opened twice in that time. Nothing was sent after the last restart either. On reopen the server
handed the model the history with the note as B's answer: 8 messages after the first restart and
12 after the second. It never handed it B as a new question.
