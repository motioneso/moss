Commit `81dc32fde` — "feat(module-sdk): add strict local-wall-clock-to-instant converter (#1869
slice 3A)". Adds to `packages/module-sdk/src/time.ts`:

- `strictLocalWallClockToInstant(localDateTime: string, timeZone: string): Date` — converts an
  offset-less local date-time (`YYYY-MM-DDTHH:mm[:ss[.sss]]`, no `Z`, no numeric offset) to the
  exact UTC instant in the given IANA zone. Rejects (never guesses): bad syntax, an unrecognised
  zone, a spring-forward gap, a fall-back fold. Detection samples the zone's settled offset a day
  either side of the wall-clock moment, builds the resulting candidate instants, and keeps only the
  ones that round-trip through `Intl.DateTimeFormat` back to the exact wall clock requested — zero
  candidates is a gap, two is a fold, one is the answer.
- `StrictLocalWallClockError` (extends `Error`, has `.reason`: `"invalid-syntax" |
  "invalid-timezone" | "dst-gap" | "dst-fold"`) so a future caller (Food's write boundary, slice
  3B — NOT this slice) can map reasons to its own bounded validation error without parsing message
  text.
- Both exported from `packages/module-sdk/src/index.ts`.
- 12 new tests in `tests/unit/module-sdk-time.test.ts` (`describe("strictLocalWallClockToInstant")`),
  including the exact exit-criterion-6 case (`2026-08-22T20:14:00` LA -> `2026-08-23T03:14:00.000Z`)
  and both DST edge cases with LA's 2026 gap (Mar 8) and fold (Nov 1).
