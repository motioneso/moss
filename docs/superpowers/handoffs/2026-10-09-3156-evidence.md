## Live demonstration

Run on an isolated install built from this branch on port 5184, with its own database and a real
Claude subscription signed in for this install only. Chat turns used the subscription's default
model; the summary job was routed to the economy model, `claude-haiku-5-5` (4 structured calls in
the install's model activity log). No responses were intercepted or rewritten. Record:
`live-before-restart.txt`, `live-after-restart.txt`.

Disclosed small budgets, so the decision would fall outside raw replay quickly:

- Summary every 3 completed turns.
- Replay budget 3000 tokens; memory seed budget 1500 tokens.

Steps and results:

1. Turn 1 (owner) made the decision: the garden raised beds use cedar. Then 7 unrelated owner
   turns, 16 stored messages in total.
2. The worker published summary revision 1, covering through message 13 ("Is mulch useful in
   summer?"). The summary text mentions cedar.
3. The app container was restarted. The thread kept the same id; the first 16 message ids, in
   order, hash to the same MD5 before and after (`29ecfdcccd33fed83e07d59095bb30a7`), running
   from `a135e34d...` to `df415820...`.
4. The chat was reopened from the conversation list in the browser. The transcript still showed
   turn 1.
5. The fresh session's replay held the summary (265 tokens) plus 3 raw messages, the 3 turns after
   the frontier. None of those 3 mention cedar, so the decision reached the model only through
   the summary.
6. Asked "What wood did we decide on for the raised beds? One sentence." The model answered
   "Cedar." Both new turns were stored on the same thread.

Notes:

- Two launch replay events with identical counts were logged after the restart, one when the chat
  opened and one when the message was sent.
- The last assistant reply before the restart reports a tool error from an unrelated note-saving tool; it does not
  affect replay.
- No native vendor compaction is used or claimed.
