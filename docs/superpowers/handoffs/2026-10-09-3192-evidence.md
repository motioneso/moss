# #3192 owner Main evidence

Main is the signed-in owner's own designation. The drawer and the Conversations overlay now pick Main as the thread that carries the Main flag and belongs to the signed-in owner. A shared thread that carries another person's Main flag is listed as a side chat. With no known owner there is no Main. Draft binding follows the selected thread, so the owner's unsent Main draft stays with the owner's Main.

## Scope limit

Ben ruled on 2026-10-09 to keep read-only viewing of shared chats out of this ticket. The ruling is recorded as a comment on #3192, and read-only viewing is now #3216, which needs a spec.

- A chat shared with you is listed in Conversations but does not open.
- The server keeps transcript reading and resume owner-only. A grantee gets 404, and the drawer reopens Conversations without changing Main or the draft.
- No sharing capability was added.
- The app map says the same thing in the assistant settings entry and the chat thread history feature.

## Red, green and negative controls

- Three overlay tests and one drawer draft test reproduce the defect: a newer shared Main listed first, only a foreign Main visible, and no known owner.
- With the owner check removed (`threads.find((thread) => thread.isMain)`), all four fail. With it restored, all four pass.
- The installed proof also fails with the owner check removed. It stops at the Conversations step because the owner's Main row reads `aria-pressed="false"`. Gate log `jarv1s_scheduled_3192_owner_main-20261009-132328`, terminal rc 1. The fix was restored afterwards.

## Installed live proof

Assertions:

1. The admin's own Main binds first. The thread list puts the shared Main first, and the privacy thread is the admin's own Main.

## Review

A fresh Opus reviewer saw only the ticket, the diff and the code-review skill.

- Must-fix: the app map claimed selecting any conversation opens its transcript. Fixed in both entries.
- Optional, not changed here:
  - Selecting a shared row while a reply streams cancels that reply before the server refuses the switch (drawer `onSelect`).
  - The server could stop sending the Main flag to grantees, which would fix every reader at once.
  - Startup draft loading keeps its own owner-Main rule, which falls back to the newest side chat.
  - A drawer without an owner id silently has no Main.
  - The shared seed is keyed on the chat script name.
