# #3275 Mid-chat tool refresh and repeated calls evidence

The 2942 and 2950 live specs now start every fresh chat through Conversations and "New side chat" instead of the removed "New chat" button. No assertion was deleted or weakened and no label was renamed. Both specs ran live against the real configured model and a real MCP tool server, with captures switched off. The drawer now shows your message and any approval request in a new side chat right away, instead of only after the reply finishes; the specs need that to approve tool calls mid-turn. Each protection fails with its guard removed.

## Scope

- 2942 live spec: no tool before refresh, approved real effect in a new side chat.
- 2950 live spec: one switch per tool row at desktop and phone width, two identical calls inside one fresh chat both reach the tool server, grouped list after Refresh.
- Capture guards on every 2950 screenshot (2942 takes none).
- Protection unit test for both specs.
- Drawer change: a new side chat shows its live turn, with two unit tests.
- Migration collision check: counts claimants by file path.
- Not touched: 3274 and 3276-3281 specs, #3210, #3273.

Should-fixes, taken:

- This doc cited an uncommitted red log. The failing assertions are now inline.

Should-fixes, left as follow-ups:

Earlier review notes, kept:

## Migration number check

`495f9061a` fixes a false collision. A branch stacked on an open PR carries that PR's migration at the same path, which the check counted as two claimants. It now groups by path. Unit test added.

This change sits outside #3275 but blocked this PR's CI. The trade-off is that two unrelated PRs adding the same file path with different contents now count as one claimant, so the check misses that case. Comparing contents as well would close that gap; no issue filed yet.
