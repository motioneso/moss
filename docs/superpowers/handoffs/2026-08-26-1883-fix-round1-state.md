## The real reason the live test kept failing

The note search was not failing at the network at all. It failed instantly, with a permission
error, making a folder it wanted to use as a model cache.

- The embedding library defaults its cache folder to a hidden folder inside its own package, under
  `node_modules`. In the container that folder belongs to the root user, while the server runs as an
  ordinary user, so the very first attempt to use it is refused.
- The image already sets aside a writable folder for exactly this purpose and mounts storage there,
  but the library does not look at that setting on its own. Nothing pointed it at the right place.
- Because the refusal is an ordinary permission error and not a network error, the new code
  correctly declined to call it a connection problem, and the user saw the plain generic message.

This is a real product fault, not a test-only one: with the local embedding engine in use, searching
your notes in a released build would have failed this way every time. Fixed by pointing the library
at the writable folder the image already provides. Deployments that do not set that folder keep the
library's own default, so running from source in development is unchanged.

New file `packages/memory/src/transformers-cache-dir.ts` plus three unit tests.
