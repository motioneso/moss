# Issue #3165 evidence: saved quiet hours carry into Profile and the alert workers

Branch `scheduled/3165-quiet-hours-carry-forward`, base `integration/scheduled-proactive`.

## Scope

- One classification over the owner's Profile quiet hours, the older nested alert schedule and the
  owner time zone. Statuses: default, carried, canonical, conflict, malformed.
- Every consumer follows the classification: Profile GET, notifications and focus, and the alert
  scanner workers.
- No migration and no upgrade-time write. A GET never writes.
- No conflict-choice editor. That is #3131.

## Change

| Area | Before | After |
| --- | --- | --- |
| Profile GET | Profile row only | Effective schedule plus authority status; the older alert schedule while in conflict |
| Profile save, chat tool | Write Profile | Lock the authority, stamp `canonical`, or keep `unresolved` on a conflict |
| Legacy alert save | Writes the nested schedule | Unambiguous owner: lands on Profile as canonical. Conflict: writes nested and freezes Profile as unresolved. Malformed: nested only |
| Locale change | Plain write | Freezes an unmarked pair whose verdict depends on the owner zone, so a zone change cannot create or settle a conflict |
| Chat undo | Restores the prior row verbatim | Restored unmarked row keeps the current marker's verdict unless it reaches that verdict unmarked |
| Chat tool result | Saved schedule | Saved schedule plus authority; Moss is told to say alert cards still follow the older schedule on a conflict |
| Notifications and focus | Profile row | Authority-resolved value through the injected port |
| Alert scanner workers | Nested schedule, locale zone | Injected resolver returns the effective schedule and its zone; null keeps the nested schedule. Locale zone still governs cap day and ranking |
| Profile screen | Controls only | Loading line, error with Try again, conflict note naming the alert schedule |

The app map is updated for Profile, Alerts, the quiet-hours feature and the proactive manifest.

## Installed demonstration

`pnpm test:uat:3165` on an isolated install, dev port 5187, image built from the branch: 1 passed
(7.0 min). Seeded rows stand in for an upgraded install. Every later change goes through the app.

- An alert-only window reads carried with no Profile row.
- The scanner worker defers a critical card to the end of that window and hides it from the card
  list.
- Before the window ends there is no notification or card. After it there is exactly one of each,
  with the same identity after a second scanner run. The Profile row is still absent.
- A restart and reload keep the window carried and write nothing.
- A legacy alert-form edit lands on Profile as canonical. A save from an older read gets 409.
- A Profile edit is canonical after reload and leaves the alert record untouched.
- The same window with the zone unset, or set to the owner zone, reads carried and writes nothing.
- A schedule conflict and an on-versus-off conflict stay unchanged through an email save, a reload
  and a restart.
- A malformed record stays unchanged through a read and an email save.
