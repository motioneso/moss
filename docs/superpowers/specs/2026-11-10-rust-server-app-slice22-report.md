## Item 1: module AI

- Modules ask the capability router, which reads the signed-in account's own provider and model rows under row-level security.
- Provider keys are opened with the instance AI key (`ai_key` in the module settings file, generated by the bundled database setup and written by provisioning).
- Without an AI key, or without an active default provider, the call fails closed (HTTP 503) and nothing is sent.
- Embeddings stay unwired and fail closed with a clear message.
- Not read yet: per-chat bindings and the per-user model override.

## Live proof

Gate `pnpm test:rust-module-ai`, real HTTPS server, throwaway Postgres, local fake provider.

- Signed out: 401.
- No provider: 503, fake provider received nothing.
- Provider and model added: 200, request went to `/v1/chat/completions` with the opened key and the chosen model.
- Provider disabled: 503 again, no new request. The key never appears in the server log.
