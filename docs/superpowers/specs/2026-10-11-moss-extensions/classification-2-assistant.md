## Surprises

Files that mix locked and open logic. Each needs splitting before an extension point is safe.

- `chat/src/live/classifier-gate.ts`. The open steps (picking the area, picking the tool, the argument questions) each check the lead and confidence bars inline, right after the classifier answers. An extension that replaces chooseArea or chooseTool would replace the bar checks too. The fix is to have an extension return only the question text and option descriptions, and keep asking, bar checks, input validation and dispatch in built-in code.
- `chat/src/live/classifier-gate-arguments.ts`. renderReplyTemplate is the only open function. Everything else in the file is an eligibility or bar check. Its rule that a missing value gives no reply (so a failed write never reads as success) must survive any custom wording.
- `chat/src/live/classifier-gate-wiring.ts`. The area description callback is open; gateRisk, the release check and the gateway call are locked.
- `packages/ai/src/structured/classifier.ts` holds no open choice of its own. The question text it sends comes from the chat gate. It is locked because it resolves the model through admin pins and carries the key-decrypt capability.
- `chat/src/memory-distillation.ts`. When and what to remember sits next to the sensitive-text checks.
- `chat/src/live/runtime.ts`. Persona text constants live inside the composition root.
- `briefings/src/compose.ts` and `compose-evening.ts`. The open composition logic calls the untrusted-data sanitiser inline on every external string.
- `notifications/src/repository.ts`. The quiet-hours deferral rule sits inside the storage method that creates notifications.
- `web-research/src/reader.ts`. extractReadableText (how page text is pulled out) is open, but it sits next to the redirect-following fetch, which is locked.
- `web-research/src/config.ts`. The result count limits (open) share one object with download, redirect and timeout limits (locked).
- `people/src/service.ts`. Accepting a match suggestion (open) shares a method with the rule that merges and splits need an explicit action (locked).
- Every `manifest.ts` is marked locked because it declares tool risk and permissions. It also holds descriptions and classifier declarations that a person might want to reword, which would need a separate hook.

Could not classify with confidence:

- `chat/src/attachments-service.ts` and `chat/src/current-view-tool.ts`. Locked because they enforce attachment ownership and page view redaction, but they may be plain storage.
- `chat/src/commitment-provider.ts` is an empty stub, so marking it open is a guess about its future use.
- `memory/src/candidate-labels.ts`, `briefings/src/fallback.ts` and `people/src/notes-format.ts` are open only for wording, and are low value.
