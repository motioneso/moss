The new `test:rust-phase6-exit-journey` runner builds the Rust shell and starts the actual HTTPS server against an isolated gate database. Generated signed fixture packages use the real registry, review, installation and lifecycle paths. There are no intercepted or rewritten network responses. The server listens on the claimed development port through a non-loopback LAN IPv4 address; both desktop and phone browser contexts use that address throughout. The address is deliberately kept out of this public report.

The journey signs in an administrator and a member through the real authentication endpoint. It browses, installs, waits for added-capability consent, checks Skip/pin after reload, approves a healthy update, removes/reinstalls, types a deletion confirmation, and restores the same two-owner ledger IDs, owners, amounts and titles. It checks member visibility and refusal of install-wide removal. Phone checks use a 390px viewport with page/dialog overflow assertions. The “Finance desktop/phone” labels identify synthetic lifecycle packages; actual Finance coverage is the cited M12 run. This is a browser on this host reaching its LAN listener, not a claim of physical-phone testing.

The separate existing runtime gate exercises real installed Wasm routes, tools, frames and worker jobs for two accounts. It first runs positive controls, accepts a signed block, removes the registry directory, drops/reopens the application, and checks that routes and queued jobs remain refused offline. This is an application/host restart, not an OS reboot or a complete network blackout. The private lifecycle gate includes guard-removal marker controls and a restored pass; the trust gate includes the actual HTTPS session and local publisher CLI.

## Limitations and known flakes

- Production registry publication and production signing-secret provisioning are not performed here. Only fixture signing keys are used. Real installers, native installation/uninstallation and clean-machine verification remain Phase 7 work.
- Part 9 explicitly records automatic administrator notice delivery as unsupported. Its [approved task brief in PR 4484](https://github.com/motioneso/moss/pull/4484) permits reporting that limitation when the existing service cannot target admins. The screen supplies a pending-request queue; that is not proof of push/notification delivery. This is an explicitly permitted limitation, not a newly waived kill gate. See [part 9 limits](2026-11-24-rust-phase6-install-requests.md).
- The original part 1/8a/8b/8d receipts include dirty files. Their commit alone does not identify all tested bytes; the receipts’ fingerprints and source reports supply that distinction. No changed-input receipt reuse is claimed.
- Part 11 fixed a serving-host startup race with a bounded real readiness check; it also isolated old Backtrack worker jobs between installed test worlds. Its request test needed a startup-refresh barrier before deliberately pausing supervisor credentials. These fixes are already in the base.
- The part 11 policy CI job once missed its ten-second app-open-refresh deadline, then passed unchanged locally and in CI. Its exact cause remains unestablished (PR 4487).
- The part 14 lifecycle CI run once stopped during reinstall Checking. The same branch and main passed locally, and unchanged CI retry passed. The cause remains unestablished (PR 4494). The old generic request-heading race was separately reproduced and fixed in the test by part 14.
- The legacy vault-upload browser timeout and meeting draft UI timeout did not reproduce on the unchanged branch/base reruns recorded in PRs 4490 and 4487. They are known intermittent checks, not defects repaired here.
- The repository notes the local module-sdk-worker unit-test mismatch and Sports live-data sensitivity. Neither is relabeled as a fresh failure or a pass by this task.
- Full foundation, all legacy browser suites, real banks/connectors, physical phones, OS reboot and production release are not certified by these focused proofs. Existing three-OS bundle evidence is historical; this Linux exit run does not repeat it.
