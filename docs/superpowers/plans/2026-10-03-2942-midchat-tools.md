# Plan: fix-2942-midchat-tools (issue #2942)

## Choice for part 1, and why

Hint, not pickup. The running chat keeps the tool list it started with because
the session token mints a fixed per-session allowlist at launch
(`packages/chat/src/routes.ts:454-468`), enforced on every call
(`packages/ai/src/gateway/gateway.ts:298-306`). Picking up new tools
mid-conversation would mean relaunching the live engine session and re-minting
its token, which reaches into the session manager's new-chat path that PR 2963
still has open, and it would widen a security allowlist behind the session's
back. The smaller safe fix is a hint: when the server refuses a call for a tool
outside the session allowlist, the refusal text names the cause and tells the
person to start a new chat. No change to token lifecycle, engine launch, or the
session manager.

The switched-off direction needs no hint (a new chat cannot restore a tool that
is off). It is already refused by the per-turn resolver
(`gateway.ts:288-296`, `executableTools` at `gateway.ts:850-852` re-resolves
active modules on every call), and part 2 proves it with a test.

   refusal string in `prepareCall` to name the cause (tool added after this

   switch-off) and assert the chat call is refused and the handler never runs.

   hint text.
