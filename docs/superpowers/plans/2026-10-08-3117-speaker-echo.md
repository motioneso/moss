# Meeting speaker echo (#3117)

## Route and evidence

Try Apple's VoiceProcessingIO for microphone + computer-audio recordings. Keep plain HAL for
microphone-only recording and never construct a microphone unit in computer-audio-only mode.
If unsupported VPIO configuration, initialization, or start fails before admission opens, allow
plain HAL on the same exact microphone only after the VPIO attempt is completely cleaned up.
Security, source-selection, callback-admission, and cleanup failures must still fail closed.
Do not alter the process tap, its exclusions, its unmuted behavior, or transcription providers.
No text-matching suppression: native incompatibility has not been established, and legitimate
repeated speech must not be removed speculatively.

Apple's [WWDC19 session](https://developer.apple.com/videos/play/wwdc2019/510/) describes device
playback cancellation with both I/O sides active. Apple's
[WebKit implementation](https://github.com/WebKit/WebKit/blob/0936c5cbe1fe4856241174b741059960db92b419/Source/WebCore/platform/mediastream/mac/CoreAudioSharedUnit.cpp)
uses VPIO with explicit microphone/output selection and silent output when no playback producer
exists. This supports the topology, not an acoustic compatibility guarantee with Moss's tap.
Whether this silent-output unit can cancel externally played system audio, rather than only its
own rendered output, is unresolved. A controlled real-Mac A/B trial must settle that question;
neither configuration tests nor a successful Start establish acoustic cancellation.
[WWDC23](https://developer.apple.com/videos/play/wwdc2023/10235/) provides minimum other-audio
ducking, not a promise of zero attenuation. Use advanced minimum ducking and require the setting
to succeed for VPIO rather than silently accepting Apple's stronger default. A fully cleaned-up
plain-HAL fallback does not request voice-processing ducking.

The [#3120 review](https://github.com/motioneso/moss/pull/3120#issuecomment-6055989334) identifies
startup fallback, harmless reference-format notices, production wiring coverage, diagnostics,
and real-device coexistence as explicit acceptance work, not proven outcomes.

## Implementation

- Enable both VPIO buses before selecting the exact microphone on global element 1 and the
  current default playback device on global element 0. Never set system default devices.
- Supply a bounded silent render callback, never microphone or process-tap samples. Use matching
  mono client formats for both VPIO sides; preserve the processed channel-0 selection rather than
  relying on implicit channel mixing. Keep sample copying and callback-admission guards.
- Limit fallback to unsupported VPIO configure/initialize/start operations before admission.
  Close admission, drain callbacks, remove listeners, and complete stop/uninitialize/dispose
  before constructing plain HAL for the same exact microphone. Never treat authorization,
  ambiguous or changed source identity, stale admission, or failed cleanup as compatibility
  failure. If teardown fails, retain cleanup retry ownership and do not open a second unit.
- A narrow endpoint-readback exception covers VPIO reporting its hidden aggregate instead of
  the selected physical endpoints. First verify the exact selected microphone and reference
  output are still alive and the default output has not changed. Discard the VPIO attempt before
  admission, complete its cleanup, then construct plain HAL for the same exact microphone.
  This is not permission to fallback on resolver, process-exclusion, permission, callback
  invalidation, or cleanup failures; those must still fail closed.
- Observe the reference output route as well as the microphone. On bus-0 format notices, re-read
  the configured input-scope client format. Unchanged client format is allowed, including
  output-scope hardware notices when VPIO resamples internally. An unreadable or changed client
  format, lost device, or changed reference route closes admission and enters the existing
  paused/source-recovery flow. Resume rebuilds after current inventory/authorization checks;
  do not silently substitute microphones or retarget a running reference.
- Emit one fixed-label voice-processing on/off diagnostic per recording epoch after the selected
  path is established, including off for plain-HAL fallback. Use distinct fixed failure codes
  for reference-route loss, reference-client-format verification, and each VPIO configuration
  write. Diagnostics remain metadata-only; do not log audio, transcript text, device names, or
  arbitrary OS error descriptions.
- Add fake-unit tests for configure/initialize/start fallback and teardown ordering, same-mic
  identity, cleanup/security/admission failures, unchanged/changed bus-0 notices, and diagnostics.
  Protect the production factory, VPIO subtype, per-bus device selection, and bus-0 reference
  format with direct configuration assertions and mutation controls. Keep existing
  capture/security controls intact; a fake's stored mode flag alone is not production proof.
- Keep the existing Meetings echo app-map feature ID, bound its description to 240 characters,
  describe plain-HAL fallback, and keep live-validation-pending wording until proof lands.
  Run all meeting-manifest tests against the actual source registry and the app-map builder.
  Include the product release note in the draft PR.

## Verification limits and live checklist

Linux cannot build Apple frameworks or provide acoustic evidence. Hosted macOS builds/XCTest
can establish compilation and synthetic lifecycle behavior; those runners do not prove speaker
cancellation, privacy permission flows, perceived ducking, or tap coexistence on real hardware.
Keep the PR draft and issue open until installed live proof is recorded.

On a real Mac, record exact build, OS, input/output devices, source mode, one on/off diagnostic
per recording epoch, and bounded results for each trial. Use the installed UI and real data;
record numerical level comparisons and assertions rather than screenshots or private audio.
All of the following remain pending:

1. A/B plain HAL against VPIO with the same built-in speakers, exact built-in microphone,
   externally played remote speech, and playback volume. Run both Zoom and browser playback;
   Moss's output callback must remain silent. Compare microphone echo and source-attributed
   transcripts to determine whether system playback is actually the cancellation reference.
   Target: remote sentences appear once as computer audio, while local speech and intentional
   repetition remain microphone speech. Include simultaneous local/remote speech and quiet
   remote speech. Report failure or uncertainty without claiming cancellation succeeded.
2. Compare perceived playback loudness and tap-captured remote-audio level before/during/after
   VPIO capture using identical speech and volume, during both local silence and local speech.
   Check transcript quality, acceptable minimum ducking, and restoration after Stop without
   clicks or a loop. Record the tap-level result separately from what the user hears.
3. Verify Zoom and Teams retain their own microphone input while Trail Marker records. Exercise
   both start orders and check remote participants still hear local speech. Include Safari-based
   meetings and Chrome with system echo cancellation where available. The independent tap must
   remain live, with selected-app/exclusion scope unchanged.
4. Configure the meeting app to use a specific non-default speaker while the system default
   stays elsewhere. Measure the effect on echo and verify capture continuity; do not assume the
   default-output reference covers that app's chosen device.
5. Verify the private VPIO aggregate is absent from the Settings microphone list and does not
   invalidate startup inventory or trip #3119's startup recheck. Confirm the selected physical
   microphone remains exact across Start, Pause/Resume, and repeated Start/Stop.
6. Test aggregate/multi-output devices (including BlackHole/Loopback where installed), AirPlay,
   and rejected VPIO configuration/init/start. Confirm unsupported startup falls back only after
   full cleanup, preserves the same mic and independent tap, and emits one off diagnostic for
   the epoch. Validate fail-closed security, identity, admission, and cleanup cases separately
   with deterministic tests; do not induce unsafe permission bypasses for live proof.
7. Switch Bluetooth from A2DP to HFP mid-meeting by opening the headset mic, and change a
   speaker's hardware sample rate. An unchanged configured client format must keep recording
   even if hardware format notices fire. A genuinely changed/unreadable client format must
   pause safely, without stale callbacks/uploads, and recover through explicit Resume.
8. Change default output, unplug the selected microphone/output, and switch Bluetooth devices.
   Confirm source-loss pause, no stale callbacks/uploads, explicit recovery, and working Resume.
9. Check microphone-only, computer-audio-only, selected-app, Pause, Stop, and repeated Start/Stop.
   Microphone-only stays on plain HAL; computer-audio-only opens no microphone and must not
   request microphone access. Check that diagnostics distinguish VPIO from plain-HAL runs.

If the native experiment fails the actual coexistence test, capture the failure before choosing
the separately authorized conservative same-time transcript fallback.
