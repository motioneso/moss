# Rust sign-in and secure network access

JS-44, Card 520, part of #4027. Implements the approved Rust port plan and data/install rules.

- Reuse Phase 2 password hashing, cookie signing, session expiry/revocation, account checks and
  runtime database roles. Browser sign-in replies contain no session token.
- Add a standalone `rust-spike/network` workspace. Its boundary checks exact Host authorities,
  exact HTTPS origins and same-origin writes before every handler. Ignore forwarded headers.
- Permit first-owner setup only through a loopback peer and loopback authority, serialized to
  avoid concurrent setup. Refuse anonymous remote setup and close setup after the owner exists.
- Require an explicit listener configuration, with sharing off by default. Recommend loopback
  for local-only use. An authenticated administrator can explicitly enable
  LAN/tailnet sharing for configured HTTPS addresses; disabling it cuts off remote requests.
- Use Rust TLS with local certificates generated by the installed OpenSSL, or supplied PEM
  certificates (including certificates obtained by the operator from Tailscale). Never install
  trust roots or change the machine's tailnet settings automatically.
- Mount the shell and private routes behind authentication, passing the authenticated actor
  through to account-specific data. Add real sign-in, setup and sharing screens using Moss CSS.
- Record failing-first boundary tests and removal controls, isolated database checks through
  verify-gate, browser proof using a second network address, and an independent read-only review.
- Keep credentials, network addresses, logs and screenshots outside this public repository.

Live state: implementation and final live/browser verification pass, including all three
removal controls. Report: `docs/superpowers/specs/2026-11-08-rust-phase4-part2-report.md`.
