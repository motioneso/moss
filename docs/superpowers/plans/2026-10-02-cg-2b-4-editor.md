## Goal and boundary

Build the connection-detail classifier section in **`apps/web/src/settings/settings-integrations-pane.tsx`**
plus a focused adjacent component and API hooks: the per-connection "Let the classifier use this
connection" switch, the explicit prepare action with its disclosure, a per-tool reviewed editor
(description, reply template, risk choice, opt-in switch), the approved/stale/failed/no-tools/
disconnected states, and a visible ineligibility reason for every tool the classifier cannot use.

This slice is **UI only**: it consumes 2b.2's storage/routes and 2b.3's prepare endpoint. It adds no
backend route, no migration, no runtime menu and no dispatch (2b.5), and no assembled live proof
(2b.6). It does not change the ordinary tool or repeat-call controls.

Determinism boundary: every label, badge, count and message renders from the detail record, the
prepare response record, or a code-authored constant; never from model prose. A model draft is shown
only as an editable field and is stored only by 2b.2's explicit save; a discarded draft persists
nothing. The connection switch never opts a tool in and never approves a draft.

## Decisions

### D1 — One new focused component; the pane stays the owner of the screen

New `apps/web/src/settings/settings-integrations-classifier.tsx` exporting:

```tsx
export function IntegrationClassifierSection(props: {
  readonly detail: IntegrationDetail;
  readonly onChanged: () => void; // invalidate the detail query
}): JSX.Element;

export type ClassifierSectionState =
  | "disconnected"
  | "no-tools"
  | "not-prepared"
  | "preparing"
  | "failed"
  | "review"
  | "stale"
  | "approved";

export function classifierSectionState(input: {
  readonly enabled: boolean;
  readonly toolCount: number;
  readonly preparing: boolean;
  readonly prepareStatus: PrepareIntegrationClassifierResponse["status"] | null;
  readonly draftCount: number;
  readonly saved: readonly IntegrationClassifierToolPreparation[];
}): ClassifierSectionState;

export const CLASSIFIER_RISK_OPTIONS: readonly {
  readonly value: IntegrationClassifierRisk;
  readonly label: string; // read "Only reads" | write "Changes a device" | outbound "Sends data out" | destructive "Sensitive or destructive"
}[];

export function classifierEligibility(
  tool: IntegrationToolDescriptor,
  entry: IntegrationClassifierToolPreparation | undefined,
  ordinaryEnabled: ReadonlySet<string>
): { readonly eligible: boolean; readonly reasons: readonly string[] };
```

`IntegrationDetailView` renders `<IntegrationClassifierSection detail={detail} onChanged={invalidateDetail} />`
as its own `<Group>` after the Tools group, so the ordinary flat/grouped tool lists and both switches
are untouched. The pure functions are exported so the unit suite asserts state selection and
eligibility without a browser.

### D2 — Section state is derived from records, in a fixed priority

`classifierSectionState` picks the first match:

1. `disconnected` — `!detail.enabled` (switch disabled; "Reconnect to change these settings.").
2. `no-tools` — `detail.tools.length === 0` ("No tools found" / "Nothing to prepare yet.").
3. `preparing` — a prepare request is in flight ("Preparing..." + Cancel).
4. `failed` — the last prepare reported `unavailable`/`unsupported_model`, or `ok` with zero drafts
   and at least one `failed` target ("Preparing failed" / "Nothing changed." + Try again).
5. `review` — transient drafts exist in this session ("Review required" + `N of M reviewed`).
6. `stale` — any saved entry has `state === "stale"` ("Needs review" + Changed badge + diff).
7. `approved` — a saved entry exists ("Approved"/"Current"); unknown-risk saved tools keep a
   visible "Risk needed" row.
8. `not-prepared` — default ("Not prepared" + Prepare N tools).

No empty section: `no-tools`/`disconnected` render inside the same Group with one quiet sentence.
Badges use existing tones: `forest` current/approved, `amber` review-needed/stale, `red` failed,
`neutral` disconnected.

### D3 — The connection switch never prepares, approves, or opts a tool in

`Switch ariaLabel="Let the classifier use this connection"` writes `classifierEnabled` through the
existing `updateIntegration(id, { classifierEnabled })` mutation. Flipping it on only marks the
connection eligible; it makes **no** model call, saves **no** tool review and approves nothing, so
"Not prepared" survives the flip until the owner presses Prepare. Flipping it off leaves saved
reviews stored (inert) and cancels no stored text. This is the "no silent opt-in on a bulk connection
switch" rule; the test asserts that turning it on writes only `classifierEnabled` and never
`saveIntegrationClassifierTool`.

### D4 — Prepare is the single explicit consent action, with cost + sharing shown before it

The "Prepare N tools" button (D8 disclosure text always visible above it) first ensures
`classifierEnabled` is true, then calls `POST …/classifier/prepare` with `force: false`. While it
runs the section shows `preparing`; Cancel aborts via `AbortController` and leaves the stored map
untouched. Responses:

- `unavailable` → "No default chat model is set." + a link to `/settings?section=assistant`
  (`INTEGRATION_CLASSIFIER_PREPARATION_DISCLOSURE` remediation path from the manifest).
- `unsupported_model` → "Your default chat model cannot draft setup notes." + same link.
- `ok` → drafts render in `review`; `reused`/`failed`/`remaining` are shown as counts of records.
  If `remaining > 0`, a "Prepare N more" button repeats prepare (unchanged entries are `reused`, so
  no repeated charge); it appears only after the current batch is saved or discarded.

Never a silent model switch: the screen never names a provider or model and never routes elsewhere.

### D5 — The review editor: drafts look different, opt-in is per tool and off by default

Each draft row (from `PrepareIntegrationClassifierResponse.drafts`) renders:

- the tool name plus a `draft` badge (visually distinct from saved rows, which show no draft badge);
- a text input `aria-label="Description the classifier sees for <tool>"` seeded with the draft;
- a text input `aria-label="Reply for <tool>"` seeded with the draft template; allowed placeholders
  `{status}`/`{action}`/`{summary}` shown as a hint;
- a `Select aria-label="Risk for <tool>"` with `CLASSIFIER_RISK_OPTIONS` plus a "Choose a risk..."
  empty option; the server hints (`readOnly`/`destructive`/`idempotent`) are shown only as a
  suggestion line ("The connection says this only reads." / "...sensitive"); conflicting hints say so
  and set nothing. Unknown risk stays unselected — never inferred from a missing hint (ruling 5);
- a `Switch aria-label="Classifier may use <tool>"`, **default off**;
- a read-only line summarising `draft.arguments` (fixed choices from the schema, or "needs a typed
  value"); `candidates` editing is deferred to 2b.5.

Tools with no draft (ineligible) render a reason row via `classifierEligibility`. Actions:

- **Approve reviewed tools** — enabled only when at least one row has a chosen risk. It saves each
  reviewed row with `saveIntegrationClassifierTool(id, toolName, body)` where `optIn` comes from that
  row's switch (so only switched-on rows are opted in) and `reviewedFingerprint` is the draft's
  `definitionFingerprint`. A `409` shows "That tool changed since you opened it. Reload and review it
  again." and invalidates the detail; nothing else is saved.
- **Discard draft** — clears local draft state; calls no save and no delete, so rejecting persists
  nothing.

### D6 — Approved, edit and opt-out without touching ordinary controls

`approved` renders one row per saved `IntegrationClassifierToolPreparation` (via
`classifierPreparationView` on the detail): the risk as a read-only word, an opt-in `Switch`, an
"Edit" quiet button that opens the D5 editor prefilled from the saved entry (PUT with the saved
`definitionFingerprint`), and a "Remove" quiet action that calls
`removeIntegrationClassifierTool(id, toolName)` (DELETE = opt out entirely) behind the existing
`confirm` dialog. Turning a saved row's switch off saves `optIn: false` (PUT), leaving the reviewed
text stored but the tool ineligible; turning it on is refused while `state === "stale"`. None of this
touches the flat/grouped ordinary switches or the repeat-call switch.

### D7 — Stale shows the before/after and a re-preparation that names its cost

`stale` lists each stale entry with a Before/After block: Before = the saved `description`; After =
the current discovered `tool.description` labelled as the connection's new description (untrusted
data, shown as text only). Actions: "Review changes" calls prepare with `force: true` (re-drafts the
stale targets; tip "Preparing again costs one more default model request"), and "Keep it off" saves
`optIn: false`. A stale save attempt from an old tab is already rejected server-side (409); the screen
maps that to the same reload prompt.

### D8 — Disclosure, manifest and app map

`IntegrationClassifierSection` renders `INTEGRATION_CLASSIFIER_PREPARATION_DISCLOSURE` (shared const)
before Prepare: what is sent, that a hosted model sends it to its provider, that preparing costs model
usage, and what is excluded — plus the per-connection classifier line "Messages and device names go
to the classifier provider." No price is quoted.

`packages/integrations/src/manifest.ts`: add feature `integrations.connection_classifier_review`
(≤ 240 chars) describing the reviewed editor, the visible ineligible reasons, and that the connection
switch never opts tools in; extend `integrations.connection_classifier_opt_in` with the ineligible
reason. Existing preparation errors/remediation are reused unchanged.

`packages/shared/src/app-map-core.ts`: extend the `integrations` core declaration with a
screen-control sentence naming the classifier section, the per-connection switch, the per-tool reviewed

## Test cases (behaviour + the failure each catches)

`tests/unit/settings-integrations-classifier.test.tsx` (jsdom + `react-test-renderer`, expected 0):

- **State selection.** `classifierSectionState` returns each of the eight states for its exact input;
  a saved entry with `state:"stale"` beats `approved`, and drafts beat `stale`. (Catches a screen that
  offers Approve on a stale review or hides a failed prepare.)
- **Reload.** Re-rendering the section with query data reflecting a saved current entry shows
  Approved/Current and the saved risk, not the stale `not-prepared` body. (Catches local-only state
  that lies after a refetch.)
- **Connection switch never opts in.** Toggling the connection switch calls `updateIntegration` with
  only `{ classifierEnabled }`, and `saveIntegrationClassifierTool` is never called. (Catches the
  silent bulk opt-in the brief forbids.)
- **Prepare consent + disclosure.** The prepare button calls
  `prepareIntegrationClassifierTools(id, { force: false }, signal)` only after the disclosure text is
  in the DOM; Cancel aborts the passed signal. (Catches a model call with no cost disclosure.)
- **Review + opt-in default.** A draft renders description/reply/risk/opt-in; Approve is disabled
  until a risk is chosen; after choosing one and switching opt-in on for one of two rows, Approve
  saves exactly that row with its draft fingerprint and `optIn: true`, and the other as
  `optIn: false` only if its risk was chosen. (Catches a bulk approve that opts every tool in.)
- **Rejection.** Discard draft clears the draft rows and calls neither save nor remove. (Catches a
  rejection that writes.)
- **Stale review.** A stale saved entry shows Before/After, "Review changes" calls prepare with
  `force: true`, and "Keep it off" saves `optIn: false`. A save that returns 409 surfaces the reload
  message and invalidates the detail. (Catches an old approval surviving a changed definition.)
- **Opt-out.** Toggling a saved row's opt-in off saves `optIn: false`; Remove calls
  `removeIntegrationClassifierTool` after confirm. (Catches a switch that only hides a row.)
- **Failure recovery.** `unavailable` and `unsupported_model` render the exact failure sentences and
  the `/settings?section=assistant` link, and show Try again. (Catches a silent switch to another
  model.)
- **No-tools / disconnected.** Both render the mockup's one-line sentence; disconnected disables the
  switch. (Catches a section with nothing useful to say.)
- **Ineligible reasons.** A muted tool, a `null`-risk entry, a stale entry and a tool with no review
  each produce their reason string; a `readOnly:true, destructive:true` conflict shows the "you
  decide" line and leaves risk unset. (Catches a silently eligible tool and an inferred risk.)
- **Negative control (observed failing):** with the switch handler's `classifierEnabled`-only patch
  replaced by one that also opts every draft in, the "never opts in" test fails. Recorded in the PR.

Extended `tests/unit/settings-integrations-pane.test.tsx`: the ordinary flat/grouped repeat-call
switches still render (existing cases) and the page now also contains the classifier switch labelled
"Let the classifier use this connection". (Catches a regression to the controls we must not change.)

`tests/uat/specs/classifier-integrations-review.uat.spec.ts` (`uatLevel: { level: "solo-admin", without: [] }`,
expected 0), driving the real screen on an isolated instance:

3. Assert Tools renders and the ordinary tool + repeat-call switches are present before any

8. Toggle the per-tool switch off through the UI; reload and assert it stayed off (real opt-out).

reason without a second request (for example if a muted tool's normalised identity is not recoverable
from the detail), stop and report to the coordinator before adding a new backend field. Owner: the
coordinator.
