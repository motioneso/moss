# Spec — issue #1974: Chat archive, settings screen half

The backend for daily chat transcript archiving already exists (merged in #1951/#1963):
`GET`/`PUT /api/me/chat-archive`, taking and returning `{ enabled: boolean, folder: string }`,
off by default, folder defaulting to `Moss/Chats`, with folder-safety validation on the server.

This slice adds the two on-screen controls Settings needs to drive that backend. No backend
changes.

## What changes

In `apps/web/src/settings/settings-ai-pane.tsx`, add a new section, `ChatArchive`, mounted in
`AssistantPane` after `YoloMode`:

- A frontend API client pair in `apps/web/src/api/client.ts`, following the existing
  `getYoloSettings`/`putYoloSelf` pattern:
  - `getChatArchiveSettings(): Promise<ChatArchiveSettingsResponse>` → `GET /api/me/chat-archive`
  - `putChatArchiveSettings(body: PutChatArchiveSettingsRequest): Promise<ChatArchiveSettingsResponse>` → `PUT /api/me/chat-archive`
  - Types imported from `@moss/shared` (already defined there).
  - A query key `queryKeys.settings.chatArchive` added next to the other settings keys.

- A `Group` titled "Save chats to Notes" with:
  - A `Row` with a `Switch` labeled "Save chats to Notes", off by default, wired to the `enabled`
    field. Turning it on requires a Notes source to already be connected (see below).
  - A `Field` with a text input for the transcript folder, showing `Moss/Chats` as the value when
    nothing has been set yet, wired to the `folder` field. Saved on blur (matching how the
    "Assistant name" field commits in `Persona`), not on every keystroke.
  - A `Note` under the folder field stating the folder rule in plain words: it is relative to the
    user's Notes source, nested folders like `2 Area/Moss/Chats` are fine, and a path starting
    with `/` or containing `..` will be rejected.
  - Save errors (a bad folder path from the server) are shown inline under the folder field using
    the exact message the server returns (already plain English, e.g. "Chat archive folder cannot
    contain a "..segment""), using `readError` from `settings-types.ts` for consistent extraction,
    not a generic toast.
  - Successful saves show a toast, matching the `YoloMode` pattern.

- **No Notes source connected:** query `getNotesSource` (already used by the Sources pane, query
  key `queryKeys.settings.notesSource`). When `data?.path` is `null`, render the section in its
  empty state instead of the switch/field: an `ai-empty` block (matching `ChatModel`'s empty
  state) saying archiving needs a connected notes folder first, with a pointer to where to connect
  one, and don't render the interactive controls. Once a source is connected, the same query key
  the Sources pane already invalidates on connect will make this section pick the controls back up
  automatically — no extra wiring needed.

- The switch and folder field are always initialized from `getChatArchiveSettings` (not assumed
  off/default) so a returning user sees their saved value, and a folder edit only changes future
  writes (already true because it's just a preference read on each archive run; no code changes
  needed there).

## What does not change

- No backend route, validation, or writer code — that shipped in #1951/#1963.
- No new components in `packages/settings-ui` — this uses `Group`, `Row`, `Field`, `Switch`,
  `Note`, all of which already exist.

## How this will be verified

- A UAT spec (`tests/uat/specs/chat-archive-settings.uat.spec.ts`) that:
  1. Loads Settings → Assistant & AI with a Notes source connected, sees the switch off and the
     folder field showing `Moss/Chats`.
  2. Turns the switch on, confirms a toast, reloads, confirms the switch is still on (persisted).
  3. Changes the folder to a nested path, confirms it saves.
  4. Attempts an invalid folder (e.g. leading slash), confirms an inline plain-English error and
     that the previous good value is not overwritten.
  5. With no Notes source connected, confirms the empty-state message is shown instead of the
     controls.
- Existing unit/component tests for the settings pane continue to pass.
- Live-path proof: the feature exercised through the real Settings screen on the live dev
  instance (switch on/off, folder change, invalid folder rejected, empty-state check), posted as a
  `LIVE-PATH PROOF` PR comment.

## Exit criteria

- The "Save chats to Notes" section appears in Settings → Assistant & AI, functions as described
  above, and reflects the already-shipped backend faithfully (field names `enabled`/`folder`,
  same default folder, same validation messages).
- No admin-only or instance-wide behavior — this is a personal, per-user setting, matching the
  existing backend scope.
- Existing settings pane behavior for Persona, Chat model, and YOLO mode is unchanged.
