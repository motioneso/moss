# Spec — issue #1949: Workshop live build, part 2 of #1889

Source: issue #1949 comment (SPEC), posted by the fleet coordinator.

## Context

Part 1 (#1888/#1940) added asking Moss for a module in chat and getting a plan back, and part of
#1945/#1948 gave the Workshop page real build and module data. This issue is part 2: make the
Workshop page live during a build, and make its three group buttons work.

## Plan, in build order

1. **Navigation on approval.** When a build plan is approved in chat, route to the Workshop page
   with the chat drawer kept open beside it. Wire this where the approval card currently starts
   the build — do not add a second start path.
2. **Live build status on the Workshop page.** Poll the build's status while it runs (current
   step / total steps, what it has written, cost so far). State must survive closing and
   reopening the tab, so read from the stored build record, not component memory. On finish or
   failure, raise a notification row. No chat messages from the background job — progress reaches
   the user only through polled status and the notification.
3. **Make the three group buttons work:**
   - Stop this build.
   - Ask for a change (opens the chat drawer scoped to that draft — the same conversation as the
     draft module's own docked drawer).
   - Turn on for everyone.
     Each button acts on the draft it sits on, never on another owner's.
4. **Ownership.** Builds and drafts stay owner-scoped end to end. Verify the row-ownership
   protection covers every new read and write this part adds, including the admin case (an admin
   does not get to see or act on another admin's drafts by virtue of being an admin).
5. **Tests** alongside each step. Use the design-system skill before touching the page's markup
   or CSS — the page was audited clean and must stay that way.
6. **Live proof on the dev instance**, recorded on the PR: start a build from chat, land on the
   Workshop page with the drawer open, watch the status advance, and exercise each of the three
   buttons once.

## Verification

- Full local gate green (via the verify-gate skill).
- Live-path proof posted on the PR per the process above: the real flow exercised on the live dev
  instance, comment starting with `LIVE-PATH PROOF`.
