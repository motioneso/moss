# Spec — issue #1982: chat archive live-path proof and readable session headings

## Background

The chat archive backend (write daily transcripts into a note) already shipped in earlier PRs
(#1951, #1963, #1974, #1980). What's left, per issue #1982:

1. Live proof that the whole thing actually works end to end on a running instance.
2. The daily note currently titles each conversation with a raw computer timestamp
   (for example `## 2026-08-25T09:00:00.000Z`). That should become something a person can
   actually read at a glance.

## Part 1 — readable session headings (code change)

Where: `packages/notes/src/daily-archive-writer.ts`, function `renderMarkdown`.

Today each conversation in the note gets a heading built from the raw timestamp of its first
message: `## 2026-08-25T09:00:00.000Z`.

Change it to a heading built from the conversation's title and its start time written in the
user's own timezone, in plain local time — for example `## 9:00 AM — Vacation planning`. If a
conversation has no usable title, fall back to just the time.

To make this possible:

- `ChatArchiveSession` (same file) gains a `title: string` field.
- `packages/chat/src/repository.ts`, method `listStoredMessagesInRange`: add the thread's
  `title` to the selected columns (join already exists via `app.chat_threads as t`), and return
  it on each row.
- `packages/chat/src/jobs.ts`, `handleArchiveDayJob`: carry `title` through when building each
  session, and pass the already-computed `timezone` (it already derives one from the locale
  preference for the day-window calculation) into `writeDailyChatArchive`.
- `writeDailyChatArchive` and `renderMarkdown` take a `timezone: string` parameter and use the
  existing `formatInZone` helper from `@moss/shared` (`packages/shared/src/time.ts`) to format
  the heading time, for example `formatInZone(first.createdAt, timezone, { hour: "numeric", minute: "2-digit" })`.

Verification: unit tests in `tests/unit/daily-archive-writer.test.ts` covering:
- a session with a title produces `## <time> — <title>`.
- a session with an empty/whitespace-only title falls back to `## <time>` (no dangling dash).
- the heading time reflects the timezone passed in, not raw UTC (pick two different timezones
  for the same instant and confirm the rendered hour differs).

Existing tests in that file and in `tests/integration/chat-archive-day-job.test.ts` and
`tests/integration/chat-archive-dispatch.test.ts` must still pass — none of them assert on the
exact heading text, only on message body content and ordering, so they should be unaffected
by the format change itself, only by the added `timezone`/`title` parameters threading through
call sites.

## Part 2 — live-path proof (verification, not code)

On the live dev instance, exercise the real feature through the UI and record what happened as
the required `LIVE-PATH PROOF` PR comment. Steps, matching the issue's checklist:

1. Turn on chat archiving in Settings (Assistant & AI pane → Save chats to Notes), pick a test
   folder.
2. Hold two short separate conversations.
3. Confirm one dated note appears in the chosen folder containing both conversations, in the
   order they happened, each under its own readable heading.
4. Repeat with a nested folder path (for example `Moss/Chats/Test`) and confirm the note lands
   there and any pre-existing unrelated note in that folder is untouched.
5. Turn the setting on partway through a day (after already having had an earlier conversation
   that day) and confirm only the conversations held after enabling appear — no historical
   backfill.
6. Hold one incognito/private conversation and confirm it does not appear in the note.
7. Confirm an unrelated, pre-existing note elsewhere in the vault is untouched by any of this.
8. Search for a phrase from an archived conversation in the Notes search and confirm the daily
   note is found.

If any of these steps fail, that is a real bug to fix as part of this issue, not just a
reporting gap — note whatever code path is responsible and go fix it before writing up the
proof.

## Exit criteria

- Heading format changed as above, with passing unit tests.
- Full local gate green (via the `verify-gate` skill).
- `LIVE-PATH PROOF` comment posted on the PR covering all eight steps above, with pass/fail per
  step and evidence (note contents excerpt, screenshot, or search result).
- Release note filled in on the PR (user-facing: readable chat archive headings).
