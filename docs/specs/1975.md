# Spec — issue #1975: make the three Workshop buttons work

## What

The Workshop page has three buttons that currently do nothing (no click handler at all):

1. **"Stop"** on a build that is in progress. Cancels the build so it does not continue past
   its current step. Because a running build step cannot be killed instantly mid-flight, "Stop"
   is a request to not continue after the current step finishes, not an instant kill.
   - New owner-scoped repository function `cancelModuleBuild` (module-builds-repository.ts):
     one scoped UPDATE that only cancels a build owned by the caller and still `planning` or
     `building`.
   - New route `POST /api/ai/module-builds/:buildId/cancel`, owner-scoped, 404 if nothing was
     cancelled.
   - Worker guard so a build cancelled mid-step does not get silently flipped back to
     `building`/`failed` when the in-flight step finishes: check cancelled status before
     launching a step, and re-check before writing status/notification after a step resolves or
     throws.
   - Frontend: wire the existing Stop button to call the new endpoint and refresh the build list.

2. **"Turn on for everyone"** on a module you are still drafting. Ships the draft so everyone
   else on the install can use it. The server side already exists (`POST
   /api/admin/modules/:id/ship`) and is already used elsewhere in the app — this is frontend-only
   wiring: call the existing ship endpoint, refresh the module lists, and show that a restart is
   needed before others see it (same message the app already shows elsewhere for this).

3. **"Ask for a change"** on a module you are still drafting. Takes you to that module's own page
   and opens the chat drawer there, so you can ask for changes the same way you would from the
   module's own page. No backend change — navigation plus opening chat.

Only the owner of a build or draft can act on it. No new database fields. No new authorization
surface beyond what already exists.

## How it will be verified

- Automated tests:
  - Repository test for `cancelModuleBuild`: cancels only when owned and in a cancellable
    status; no-ops otherwise.
  - Route test for the new cancel endpoint: success case and 404-when-not-found/not-owned case.
  - Worker test(s) covering both guard points: a build already cancelled does not get
    re-launched, and a build cancelled while its step was running does not get flipped back to
    building/failed afterward.
  - Frontend test asserting each of the three buttons calls the right handler when clicked.
  - Existing design-system class-name test for the Workshop page must still pass unchanged.
- Full local gate green (via the verify-gate skill, never run directly).
- Live-path proof on the live dev instance: start a build from chat, click Stop and confirm it
  stops; click "Ask for a change" and confirm it opens that module's page with chat open; turn a
  draft module on for everyone and confirm it reflects the restart-required state.
