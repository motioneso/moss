# Spec 1971 — edit an already-saved medication schedule with the builder form

## What this changes

The "Manage medications" window lets you add a medication with the six-choice builder form
(#1970), and remove one. It has no way to change one that already exists — the only way to alter
a mistake is to delete it and start over, losing the dose history tied to it.

This adds an "Edit" action to each medication row. Pressing it fills the same builder form with
that medication's current name, dose, schedule and reminder setting, so it looks exactly like the
row was just filled in by hand. Changing anything and pressing Save sends the whole schedule back
to the server as one update, the same all-or-nothing way the server already accepts edits (added
in #1968). Pressing Cancel, or opening a different medication's edit, drops the in-progress change
and returns the form to its normal "add a new one" state.

Only the six schedule types the builder itself can create are editable this way: every day,
certain days, every so often, monthly, in a cycle, only when needed. (The server also stores a
seventh, older type from before the builder existed; this work does not add an edit path for it,
because the builder has no screen for it in the first place — out of scope here, same as it was
for #1970.)

## Why now

Reuses the validation and request-shaping the create side already has, and the server-side PATCH
support #1968 already shipped and tested. The only new work is: read a saved medication back into
the form's shape, and wire the Save button to PATCH instead of POST when a row is being edited.

## Behavior

- Each row in the medication list gets an "Edit" button next to the existing remove button.
- Pressing Edit:
  - Fills the form (name, dose, schedule choice and its fields, start date, reminder switch) from
    that medication.
  - Switches the section heading from "Add a medication" to "Edit medication".
  - Switches the button from "Add medication" to "Save changes".
  - Shows a "Cancel" button next to Save changes.
- Pressing Save changes sends the full schedule (same shape the create request already builds) as
  a PATCH to that medication's id. On success the list refreshes, the form clears, and the section
  goes back to "Add a medication".
- Pressing Cancel clears the form back to empty and returns to "Add a medication" without sending
  anything.
- Pressing Edit on a different row while one is already open in the form switches straight to
  editing the new row (no separate confirm step — nothing has been sent yet, so there is nothing
  to lose).
- The same field-by-field problem messages that block Add today (missing name, incomplete
  schedule, bad date, etc.) also block Save changes.
- Removing (deactivating) the medication currently open in the form cancels the edit and returns
  to "Add a medication", since there is nothing left to save changes to.

## Out of scope

- Editing a medication of the legacy "every N hours" type (no builder screen exists for it,
  before or after this change).
- Any change to how removing a medication works.
- Any change to the server. #1968 already added and tested the PATCH endpoint this uses.

## How it will be verified

- Unit tests in `apps/web/src/wellness/medication-schedule-form.ts`'s test file
  (`tests/unit/wellness-med-builder-form.test.ts`): a function that turns a saved medication of
  each of the six types back into the form's shape, round-tripped through the existing
  request-builder, matches what was saved.
- Component tests in `tests/unit/wellness-manage-meds-modal.test.tsx`: pressing Edit on a row
  fills the form and swaps the heading/buttons; Save changes calls the update function (not
  create) with that medication's id and the edited fields; Cancel restores the empty add form
  without calling anything; editing a second row while the first is open switches cleanly.
- Live-path proof: on a live dev instance, add a medication through the form, edit it to a
  different schedule type, save, close and reopen "Manage medications", and confirm the row shows
  the new schedule.
