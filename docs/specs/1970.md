# Spec — #1970 medication builder form

Approved spec, posted as the `SPEC` comment on issue #1970 and copied here so the branch
carries it. Source of truth is the issue comment.

Scope: the Add Medication builder form only (piece 3 of the #1965 re-slice). Editing an existing schedule is piece 4 (#1971) and must NOT be included in this PR.

Prerequisites already merged: server-side schedule storage and editing support (#1968), plain-language schedule summary (#1969). Build on those; do not reimplement them.

Requirements:

1. The form can create a medication with any of the six schedule types: daily, selected days, every interval, monthly, cycle, and as needed.
2. Every schedule type allows setting a start date.
3. Reminders can be turned on or off per medication.
4. Before saving, the form shows the plain-language summary (from the #1969 work) and the next three computed doses, live-updating as the user changes inputs.
5. Saving goes through the server-side support added in #1968.

Done when: every schedule type can be created through the form, the preview matches what was picked, and the whole flow is proven working on a real running instance (real browser against the real server, not mocked data).

Guardrails carried from the parent: no schema changes beyond what #1968 already added; keep the form usable on a phone-width screen; plain-language labels, no internal jargon in the UI.
