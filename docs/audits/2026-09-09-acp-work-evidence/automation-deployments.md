## Counts and what effectiveness means

Within cutoff, guard log records **21 normal notes-confirmed reset completions**, **2 stuck-reset completions** (one the erroneous PM reset), **11 skipped rounds**, and **34 ordinary reset requests**. These are operations, not tokens saved. Restarts can abandon rounds; counts need not balance. Watchdog records **one actual nudge**; log-only “nudged,” “escalated,” and “would send it a stop” are not actions.

Node sidecars poll without model inference. Their own Opus implementation/debugging conversations are outside original room token totals. Auto-reset/watchdog messages delivered into room do cause room-agent model work, already part of room transcripts; do not count them again as an added sidecar bill. No quantified net savings can be inferred from successful reset count alone.

## Limits that remain in automation itself (read-only findings)

- “Open, not started” reset-ask wording in `~/viberoom-token-work.md` is stale: current source and 13:52 restart prove it shipped. Mute→reset→unmute and stale-note-at-reset revalidation are **not** implemented: normal path waits up to 20m after initial note check and then respawns (`memory-guard.mjs:179`–**200**). Stuck path only tests nonempty file (**214–226**).
- Watchdog’s proposed AWAITING-BEN suppression is **absent from current script**; only `needs-ben` escalation exists. Plan status “proposed, not built” is obsolete, but not every proposed safeguard was built.
- Watchdog current `classify` clocks persist across idle periods (`stall-watchdog.mjs:100`–**109**), unlike fixed guard. A newly awakened agent with unchanged counters can be immediately classified stale. Because `WATCHDOG_STOP` is unset this is not currently an automatic cancel, but it weakens stall classification.
- Watchdog’s `guardResetting` parser expects a single-word room name (`stall-watchdog.mjs:198`, `/\] \S+\/(\S+) /`), whereas actual log has `ACP Work/…`; it fails to recognize ACP Work reset entries. Thus proposed guard-reset suppression is not reliable for this room. Also uses 35m lookback while guard can wait 3h. Parent may include these narrowly as current limitations rather than expand audit into a new implementation project.
- Unlike plan’s chat-only activity test, current fingerprint counts all non-watchdog messages (`stall-watchdog.mjs:115`, **129–138**). System notices can reset quiet clock.
- Claims “real work always moves token count” in guard comments are assumptions, not validated fact; provider reporting gaps and long in-flight turns limit certainty. PM regression proves thresholds must not substitute for lifecycle correctness.
