## Implemented boundary

Auth runtime shares one invalidation source among real Better Auth session deletion hooks,
explicit session-service revocations and admin revoke. Notifications occur before deletion and
at completion (SQL uses finally), retiring bindings created while deletion was pending. Runtime
shutdown closes subscriptions before the auth pool. Events project only owner/session row IDs,
never vendor row tokens. Per-input checks are supplemented by active polling and push retirement.

The opt-in Unix server issues at most four fixed owner bindings, consumes each viewer once,
bounds all accepted sockets and global actual outstanding authorization work, and returns only
correlated fresh-check replies within two seconds. Closing a socket does not release a still-
pending auth promise's budget. The client rejects foreign/uncorrelated/changed metadata, checks
idle liveness every two seconds, expires absolutely and invalidates on denial/deadline/channel
loss. Gateway composition must synchronously connect its invalidation callback to receiver
fencing; that installed path is future work.

The private canonical parent must have mode0700 and trusted ancestors. The server binds in its
exclusive0700 child, chmods0600, then publishes via exclusive hardlink. Node closes only the
private bind path; explicit published-alias deletion requires matching dev/ino. Failed publication
preserves existing listeners/files; cleanup uses nonrecursive rmdir. Close shares one promise.
