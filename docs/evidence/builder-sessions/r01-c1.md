## Approved storage and record contract

Proposed table: **`app.chat_acceptance_attempts`**, in the selected installation's local PostgreSQL data volume. Proposed migration location: **`packages/chat/sql/<next-free-number>_chat_acceptance_attempts.sql`**. Select the number only after authorization and baseline refresh; never edit an applied migration. No SQL or migration was created.

Use one logical record per owner-requested test attempt, with bounded, typed evidence entries for repeated executions/sends. Keep these groups distinct in the implementation contract:

| Group | Named proposed fields / evidence |
| --- | --- |
| Identity and applicability | `attempt_id`, `owner_user_id`, `journey_id`, `case_id`, `case_revision`, `test_window_id`, `applicability_revision` |
| Version tested | `candidate_commit`, `installed_artifact_identity`, `target_id`, `target_version`, `configuration_identity`; use opaque identifiers and a non-secret allowlist, never a configuration dump |
| Existing-record joins | Nullable `reminder_id`, `reminder_version`, `reminder_run_id`, `activity_request_id`, `thread_id`, `source_message_id`, `result_message_id`; verify each reference belongs to the same owner |
| Attempt lifecycle | `started_at`, `accepted_for_execution_at`, `finished_at`, `expires_at`; UTC timestamps with evidence provenance |
| Consent | `consent_window_id`, `consent_rules_version`, `consent_granted_at`; copied evidence is not a substitute for checking current consent before collection |
| Save | `saved_at` and reference to the existing saved responsibility; absent when no responsibility was created |
| Trigger | `trigger_evidence`: event identity, kind, execution/retry identity, timestamp and existing correlation reference |
| Send | `send_evidence`: event identity, execution identity, transport, requested/accepted/rejected/unknown stage, timestamp and safe deduplication/correlation reference |
| Durable result | `durable_result_evidence`: committed run/message/result identity, outcome code and timestamp; do not infer this from send acceptance |
| Observation | `observed_receipt_evidence`: result identity, observation timestamp and method; distinguish client-visible acknowledgement from explicit owner verification |
| Evaluation | `expected_outcome_code`, `actual_outcome_code`, `evaluation_status` and allowlisted failure category; preserve unknown/unresolved states |

This is a proposed record contract, not applied DDL. The builder/reviewer must settle SQL types, bounded evidence encoding and atomic updates before implementation. Missing run/activity/message IDs stay absent, including for refused, cancelled, silent or unfinished attempts. Do not fabricate a run or message to make a join succeed. Later IDs may attach to the same attempt without changing its original identity, consent evidence or candidate version.

Evidence entries retain distinct event identities and timestamps; duplicate delivery and extra consequential sends must remain visible. Worker retries keep the same user attempt ID and have separate execution identities. Replaying the same evidence event must not create a second count. Later passing attempts supplement earlier failures rather than replacing them.

The ledger cannot schedule, resend, edit, cancel, complete or recover a task. Read task state through existing interfaces; do not add a second source of task truth. Following codebase-design, place the evidence interface at the existing save/run/result seams, keep lifecycle and join validation inside the owning module, and test through that interface. Do not introduce a hypothetical general analytics adapter.

## Approved privacy, retention, deletion and consent

- Collection defaults off. Each owner must explicitly opt into a named test window; enforce its scope and end time and recheck current consent for every collection/write/retry.
- Owner-only access must use the existing data-context/RLS pattern, including workers. Admin configuration power grants no private-data bypass. Treat this as an implementation requirement, not a security property proved by this packet.
- `expires_at` is no later than 30 days after `started_at`; retries, late results and edits cannot extend it. Delete earlier on owner request, account deletion, related-record deletion, or consent withdrawal.
- Withdrawal stops collection and deletes that window's records. Related-record deletion removes the linked attempt/evidence rather than keeping an orphan archive. Deleting evidence must never delete the underlying task or result.
- Backups require an explicitly approved expiry and restore-time deletion policy before collection. Do not promise immediate erasure from existing backups. Restores must not expose expired/revoked records or re-enable consent. The installation's actual backup policy remains unverified.
- Store no raw source, message bodies, prompts, secrets, source-content metrics, unrestricted error text, screenshots or attachments in the ledger. Error/outcome values are controlled codes. Do not copy a full activity record.
- No analytics service or off-machine measurement. Sharing/export and off-machine backup of measurement data require separate explicit consent. This public repository packet contains rules and synthetic field names, never actual owner records.
